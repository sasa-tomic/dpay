# 2026-08-18 — The IC user-principal rail: proof-of-concept + product switch plan

> **Decision (founder, 2026-08-18):** switch the IC rail from facade-custody to a
> **user-principal rail** — the device's raw Ed25519 key becomes a self-authenticating IC
> principal, user funds sit at `Account{owner: <user principal>}` DIRECTLY on the external
> icrc ledgers, and the app signs full IC request envelopes locally. **No feature flags, no
> legacy paths, no migration** — no prod users yet; this is the moment. The PoC below is
> BUILT, AUDITED, AND MAINNET-PROVEN; this doc is both the record of that proof and the
> work order for the product cutover.
>
> Why: the facade-custody model makes "non-custodial" a *promise* (the canister's wasm +
> its controller honor user signatures) rather than a *property* (the chain itself
> authenticates the payer). See CODEBASE_ANALYSIS.md §risks 1 — an ungoverned code
> controller can upgrade the facade to drain 100% of IC-rail balances. On the user-principal
> rail, the facade leaves the authorization path entirely; an evil dpay canister upgrade
> CANNOT move user funds. Governance hand-off (GOVERNANCE.md) remains desirable for
> whatever the facade still operates (catalog/DUSD faucet), but it stops being
> load-bearing for user funds.

## 1. What exists now (this session, uncommitted — commit as one unit)

Three new crates + recipes, all offline except the two opt-in mainnet probes:

- **`crates/dpay-icp`** — the pure rail core (deps: `ed25519-dalek` + `sha2` ONLY;
  wasm32-safe, no transport, alloc-only, zero unsafe, panic-free on hostile input):
  - `Principal` — self-authenticating derivation `SHA224(DER-SPKI 44B)‖0x02`, textual
    base32-CRC32 codec (round-trip-proven vs `ic-principal`), `from_text` canonical check.
  - `request_id` — the IC request-id hash (14/14 official ic-transport-types vectors);
    signature = ed25519 over `b"\x0Aic-request"‖request_id`.
  - `sign_update` / `sign_query` / `sign_read_state` — full CBOR envelopes, **byte-identical
    to ic-agent 0.48.1 output including the signatures** (golden-proven: query, read_state,
    call+nonce, query+nonce).
  - `icrc` — hand-rolled DIDL codecs: `transfer_arg`/`approve_arg`/`balance_of_arg`/
    `allowance_arg` (byte-identical to `candid` 0.10.22 encoding of the icrc-ledger-types),
    `decode_transfer_result`/`decode_approve_result` (the BARE variant shape the real
    ledger replies — `ApproveResult::Ok(u64)` carries the block index), `decode_int`
    (nat8..64/int family). uleb/sleb128 readers are STRICTER than production candid
    (overlong/non-canonical encodings → Err, never panic, proven in debug AND release with
    60k-probe fuzz).
- **`crates/dpay-icp-tests`** — PocketIC `make_live()` e2e (the gateway runs the
  PRODUCTION `ic_validator`): real `ic-icrc1-ledger` + mock minter; 6 tests — user
  transfer, approve+retrieve offramp, bad-sig→400, expired→4xx, replay-executed-once,
  principal round-trip on-ledger. **`just test-icp`** (~7.5 s, ON the `check` hot path).
- **`crates/dpay-icp-e2e`** — (a) offline dfx-replica proof: env-gated tests +
  `scripts/icp-replica-e2e.sh` + **`just test-icp-replica`** (a SECOND independent
  ingress implementation accepting our bytes: 202 → read_state poll → certified
  `request_status` → decoded reply; bad-sig/expired negatives). (b) opt-in mainnet probes
  (NEVER in check/verify; updates only against OUR canisters ssqti/td2nx; fixed throwaway
  seeds): **`just ic-mainnet-probe`** (signed queries vs DUSD + ckBTC, bad-sig control)
  and **`just ic-mainnet-update-probe`** (`scripts/icp-mainnet-update-probe.sh`; signed
  UPDATEs vs mainnet).
- Root wiring: workspace members (+`dpay-icp`,`dpay-icp-tests` in default-members;
  `dpay-icp-e2e` deliberately NOT default), `sha2` workspace dep, `test-icp` in `check`,
  `docs/CANISTERS.md` ckBTC ledger id corrected to `mxzaz-hqaaa-aaaar-qaada-cai` (the old
  quoted form was invalid base32 — CRC-verified).

## 3. Target architecture (the cutover)

- Funds: `Account{owner: user_principal(pk), subaccount: [0;32]}` on the SAME external
  ledgers (ckBTC `mxzaz-hqaaa-aaaar-qaada-cai`, ckUSDC `xevnm…`, ckETH `ss2fx…`, DUSD
  `td2nx…`). One principal = the existing IC identity pubkey; same seed, same backup.
- Authorization: NONE by dpay. The app signs envelopes (dpay-icp → UniFFI/wasm shims) and
  POSTs to `https://icp-api.io/api/v2/...` directly. The relay/facade leave the
  value-movement path entirely.
- Pay: request QR carries `{ledger principal, payee principal (or account text), amount,
  currency}`; payer signs `icrc1_transfer` (expiry now+240–300 s); payer's phone submits
  (online) OR the merchant submits the envelope within the ~5.5-min ingress window
  (offline-pay; the envelope arg is plaintext DIDL — merchant can read but not alter).
- Offramp: user signs `icrc2_approve(spender=minter)` + minter
  `retrieve_btc_with_approval` / ckETH `withdraw_erc20` envelopes (dual-ledger approve
  for ckERC20 as today, but user-signed).
- Deposits: ckBTC `get_btc_address(owner=user, subaccount)` (accepts arbitrary owners —
  proven in mock, mirrors real candid); ckERC20 onramp is ALREADY principal-based
  (`principalAsBytes32`) — it was never facade-custodial.
- Balances: signed `icrc1_balance_of` queries per ledger, app-side polling. History:
  `icrc3_get_blocks` client-side (recent window) — relay indexer later if needed.
- Receipts: the facade's Ed25519 receipt DIES. Replacement: certified `read_state`
  `request_status/<rid>` (the rail already decodes the subtree) + block index; trustless
  verification = on-device certificate-chain check vs the pinned subnet root key (W6).
- Clock: read `ic:time` from `GET /api/v2/status` (free, unauthenticated) before stamping
  ingress expiry; refuse to sign on large skew.
- Nonce: NOT used — request_id dedup + `memo` as the reconciliation key (re-signing for
  retry FORBIDS itself: new expiry = new rid = double-pay; identical-byte resubmit is the
  only safe retry — enforced by mainnet observation above).

## 4. Workstreams (each independently gate-able; sizes are focused-session units)

- **W1 App submission client (S):** RN + wasm shim for `POST /api/v2` (fetch), envelope
  chunking into the existing NFC framing (2 frames), `/api/v2/status` clock sync, catalog
  gains per-currency `{ledger principal, fee, decimals}` (verify what the relay catalog
  already carries).
- **W2 Payer flows (M):** PayMode/WithdrawSheet rewired to envelope signing; the 292-B
  wire/`signAuthorization` surface RETIRES on the IC rail (SOL rail untouched); NFC pay
  carries the envelope; honest pending UX for the 2–5 s consensus window + the 5.5-min
  submission deadline.
- **W3 Merchant flows (M):** ReceiveMode/NFC reader: submit payer envelope, poll
  read_state, decode result, display Paid; interim receipt = request_status + balance
  recheck (honest about trust), W6 upgrades it.
- **W4 Deposits (S):** user-principal addresses everywhere the facade subaccount used to
  be (ckBTC address query; ckERC20 already principal-based; DUSD/DEMO direct sends).
- **W5 Real-minter deltas (M + founder KYC):** dust `retrieve_btc_with_approval` on the
  REAL ckBTC minter (KYC'd address, ≥50k sats) to observe allowlist/async/min-amount
  semantics; read-only `get_minter_info` probe first (S).
- **W6 Trustless receipts (M):** BLS threshold-sig verification of the read_state
  certificate vs pinned subnet pubkey, in dpay-icp (wasm-safe pairing crate — evaluate
  size; this is the only new crypto).
- **W7 Facade + relay retirement (S):** delete settlement/receipt/mint surfaces from the
  product path (facade reduces to catalog/DUSD-faucet or retires; `/pay`,`/withdraw`,
  `/receipt*` relay routes die; `EXPECTED_RECEIPT_PUBKEY` retires). DUSD needs a faucet
  path that does not depend on the facade's custody role (governed minter account or
  retire DEMO). GOVERNANCE.md simplifies: controller hand-off stops being user-funds-
  load-bearing the moment W2+W3 land.
- **W8 Test/gate rewrite (S-M):** e2e flows (FLOWS.md renumber), jest, device gates
  (`just app` self-check gains an envelope round-trip), retire wire-parity surfaces tied
  to the old rail. Keep: SOL rail, campreview, AID parity (AIDs unchanged), ckERC20
  onramp e2e.

Gates to keep green throughout: `just check` (now includes `test-icp`),
`just test-icp-replica` (pre-merge for any rail change), opt-in
`ic-mainnet-probe`/`ic-mainnet-update-probe` (release-candidate ritual), `just verify`.

## 5. Risks / open questions

1. Real ckBTC minter semantics (KYC, async, AlreadyProcessing contention) — mocked
   exactly at the candid layer; unproven at the semantics layer (W5; founder-owned KYC).
2. 5.5-min merchant-submission window is an IC-ingress property, not ours — product UX
   must treat "not submitted in time" as an honest pending/unknown (same class as SOL
   blockhash expiry).
3. W6 BLS verify is the only new cryptographic dependency — evaluate wasm32 pairing
   crate size before committing to on-device verification; interim (pinned-relay) is
   available but must be labeled honestly.
4. Ledger wasm version drift (third_party vs deployed) — watch, S.
5. Ingress rate limits: irrelevant at human POS tempo; only relevant if we ever batch
   (we don't — no relay in the path).
6. PocketIC `make_live` leaves gateway threads at test exit (nextest LEAK markers) —
   cosmetic, pre-existing class.

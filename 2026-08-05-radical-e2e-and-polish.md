## The open opportunity (the radical levers that remain)

The harness is **pixel-blind by design** (AGENTS.md: "the e2e net matches testID + textContent only").
Screenshots are captured (`e2e/shots/`) but never compared. This is the single largest remaining
structural gap: a style/layout regression (the documented `styles.ts` single-block blind spot, a dropped
import, an overflow, a contrast change) sails through `just verify` and only explodes on a device.

Pair that with: (a) failure diagnostics that drop only a stack trace (no screenshot/DOM/console at the
RED point), (b) no watch/dev-loop mode (every iteration re-runs the whole suite or a manual filter), and
(c) a few coverage classes the current flows don't assert (a11y labels, the receipt-reject path, deep
decimal formatting). These four together are the radical harness lift.

## Phase 1 — Visual regression harness (pixel-diff baselines)  [HIGHEST VALUE]

**Goal:** a committed set of baseline PNGs; a flow that re-captures each primary surface and fails on
pixel drift beyond a tolerance. Catches the exact class of regression that sails through `verify`.

**Approach (TDD):**
1. **RED:** write a probe that captures the wallet-home surface, then perturbs a style (e.g. bump
   `S.balAmt.fontSize` by +1 in-memory via a test-only override) and re-captures → assert the diff
   exceeds tolerance → test FAILS without the comparator, PASSES (RED→GREEN) once the comparator exists.
2. Build `e2e/harness/pixel.mjs`: pure pixel-diff (PNG decode via the vendored `pngjs` already pulled
   transitively, or a tiny pure-JS decoder; **no new native dep**). Returns `{matching, total, pct,
   diffPath}`. Threshold tunable per-surface (default 99.5% — fonts/AA vary slightly run-to-run).
3. New flow `40-visual-regression.mjs`: onboarded wallet → capture the 5 primary surfaces already toured
   by flow 35 (Pay / Receive+QR / Balances / Settings / Ledger) into `e2e/shots/baselines/`, diff each
   vs. its committed baseline, fail with a side-by-side diff PNG on drift. First run = baseline seed
   (`DPAY_E2E_REGEN_BASELINES=1` mirrors the wire-layout regen pattern).
4. Just recipe: `just e2e-visual` (regenerates + runs only flow 40); wire into `just verify` once stable.
5. Commit baselines. **The baselines are the contract** — a future PR that intentionally changes a
   surface regenerates them and the diff is reviewable in the commit.

**Safety:** headless chrome + `--force-color-profile=srgb --font-render-hinting=none` + the existing
`FREEZE_CSS` (animations/transitions/caret off) already stabilize rendering; the remaining variance is
font AA, well under a 0.5% threshold. Flow 35 proves capture is deterministic (its 5 shots have been
byte-stable across the 08-03 + 08-04 commits).

**Confidence:** 8/10 correct, 7/10 safe (pure addition; no existing flow touched).

## Phase 2 — Failure diagnostics capture (debuggable errors)

**Goal:** when any flow goes RED, auto-dump to `e2e/shots/failures/<flow>-<timestamp>/`: (a) screenshot
  at the failure point, (b) DOM HTML snapshot, (c) the console log buffer (info/warn/error timeline),
  (d) the requestfailed log, (e) the last N driver actions (a timeline the Driver records). Today a RED
  drops only `err.stack` — debugging means re-running with `DPAY_E2E_CONCURRENCY=1` + manual probing.

**Approach:**
1. Add `Driver.startTimeline()` — every `click`/`type`/`eval`/`navigate` pushes `{t, op, arg}` to a ring
   buffer. Cheap (the suite is <2k driver calls total).
2. Add `Driver.dumpDiagnostics(label)` — writes screenshot + `.dom.html` + `.console.log` + `.actions.json`
   to `e2e/shots/failures/<label>/`.
3. `runOne` in `run.mjs` wraps `mod.run()` in a try/catch: on throw, call `driver.dumpDiagnostics` (the
   driver is reachable via a per-test WeakRef registry the `setup()` populates) before `env.stop()`.
4. RED→GREEN: a deliberate failing flow (temp test) asserting the artifacts exist + are non-empty.

**Confidence:** 8/10 correct, 9/10 safe (only fires on RED; existing GREEN paths unchanged).

## Phase 3 — Watch mode (seconds dev loop)

**Goal:** `just e2e-watch [filter]` — re-runs the filtered flows (default: the flows matching the
  last-edited app file, or `pay` journey) on every change to `app/`, `e2e/`, or `crates/dpay-core`. Sub-
  second feedback while iterating on a component.

**Approach:**
1. `e2e/watch.mjs`: chokidar-free (use Node's `fs.watch` recursive on Linux) watcher; debounced 300ms;
   on change, resolve which flows to re-run (map app file → journey via a small static table: e.g.
   `app/components/PayMode.tsx` → `pay` journey), then invoke `runPool` with that subset. The shared
   session (relay + web + browser) is reused across re-runs — only the per-test contexts churn.
2. Just recipe: `just e2e-watch` (all), `just e2e-watch pay` (journey). Prints a stable TUI-like header
   (GREEN count + last-run time) so the loop is glanceable.
3. Optional: on a GREEN re-run, clear the terminal; on RED, print the failure summary + the diagnostics
   dir path (from Phase 2).

**Confidence:** 7/10 correct, 9/10 safe (additive recipe; the existing `just e2e` path is untouched).

## Phase 4 — New coverage (a11y + receipt-reject + decimal edges)

Each is a new flow, TDD RED-first. No app change unless a flow surfaces a real bug (then fix that bug as
its own unit).

- **Flow 41 — a11y census:** walk every primary surface; assert every interactive element
  (`Pressable`/`Text input`/tab) has a non-empty `accessibilityRole` + `accessibilityLabel`, and primary
  controls additionally have an `accessibilityHint`. Catches the class "a developer adds a button and
  forgets the label." Driver exposes this via RNW's `aria-*` attributes (verify they render).
- **Flow 42 — receipt reject:** a malicious/tampered receipt (mutated amount or wrong pubkey) must be
  rejected by `verifyOutcomeReceipt` and the UI must show a truthful "couldn't confirm" — never a false
  ✓. Pairs with flow 30 (trusted receipt). Proves the MC4 close on the harness side.
- **Flow 43 — decimal format edges:** build requests in 8-dec (ckBTC) + 18-dec (ckERC20) amounts; assert
  the review screen + history render the exact decimal strings (no rounding, no scientific notation, no
  trailing-zero drift). Covers the MC1 units-2-4 matrix the 08-03 report flagged as founder-outer-loop
  for `dpay-sim` — this is the browser-reachable slice.

**Confidence:** 7/10 correct, 9/10 safe (new flows only).

## Phase 5 — Tech-debt polish (DRY the Wallet god-component; fetchWithTimeout)

harness's `lib.mjs` relay helpers both carry the same `AbortController + setTimeout + clearTimeout`
incantation. Single source of truth.
